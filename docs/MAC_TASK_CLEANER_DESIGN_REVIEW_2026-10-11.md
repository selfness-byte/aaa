# 맥 작업정리 v1 — 설계 검토 및 개발 인계

- 문서 작성일: 2026-10-11 (Asia/Seoul)
- 대상 저장소: `selfness-byte/aaa`
- 대상 환경: Apple Silicon M1·메모리 8GB를 기준으로 한 macOS 앱 설계
- 문서 성격: 이 대화에서 합의한 설계, 검토 지적, 수정 보고, 다음 검증 범위의 통합 기록
- 작업 범위: 문서 추가만 수행. 제품 코드 변경, 빌드, 테스트 재실행, 실제 프로세스 종료는 포함하지 않음.

> **핵심 원칙**
> 사용하지 않는 것으로 추정되는 프로세스를 골라 종료하는 앱이 아니다. 관측한 사실과 불확실성을 보여주고, 사용자가 선택한 지원 대상 실행에 대해서만 보호 조건을 재확인한 뒤 일반 종료를 요청한다.

## 1. 현재 상태와 증거 수준

본 문서는 새로운 실행 결과나 최신 소스 전체에 대한 완료 인증서가 아니다. 다음 구분을 유지한다.

| 구분 | 기록 기준 |
| --- | --- |
| 합의된 설계 | 이 대화의 수정 명세와 최종 검토 의견을 정리한 요구사항 |
| 사용자 제출 실행 보고 | 사용자가 제공한 로그·소스·수정 설명. 작성자가 이번 작업에서 직접 재실행한 결과가 아님 |
| 이전 검토 기록 | 이전 대화에서 수행했다고 기록된 클라우드 검토. 그때의 버전과 코드 조각에 한정 |
| 미검증 | 최신 전체 패키지의 독립 재실행, 실제 AppKit/Darwin 연동, M1 성능 측정 등 |

### 최신 제출 실행 보고 [S3]

| 항목 | 제출된 값 |
| --- | --- |
| 실행 명령 | `swift run MacTaskCleanerTestsRunner` |
| 계산 테스트 | 14개 |
| 모의 상태 머신 테스트 | 18개 |

이 값들은 사용자 제출 로그에서 가져왔다. 53개는 직전 보고의 52개에 양수 확인 단언문 1개를 추가한 집계와 일치한다. 테스트 러너의 3.007ms는 앱의 성능 목표를 측정한 결과가 아니다.

이전 첨부에는 20개 테스트·25개 단언문 [S1], 그 다음 첨부에는 29개 테스트·48개 단언문 [S2]의 전체 코드와 보고가 있다. 이 자료를 최신 32개·53개 버전의 전체 소스로 취급하지 않는다. 최신 변경은 이후 대화의 코드 조각과 수정 보고로 제공됐다.

문서 추가 직전 저장소의 `main` 트리 조회에는 `README.md`만 있었다. 따라서 이 문서는 저장소에 이미 올라온 최신 구현을 검토한 보고서가 아니라, 대화에서 진행한 설계·코드 검토를 저장소로 인계하는 문서다.

## 2. 제품 범위와 제외 항목 [S3, S4]

### 제공할 기능

메뉴 막대에서 CPU·메모리·스왑과 메모리 압박 이벤트를 표시하고, 앱 및 프로세스를 관찰한다. 사용자가 선택한 지원 대상 앱에 일반 종료를 요청하고 그 결과를 관측한다. 보호 설정과 요청 기록을 관리한다.

### v1에서 제공하지 않는 기능

- 자원 사용량, 창 유무, 비활성 시간을 근거로 한 자동 종료·종료 추천.
- CLI 도구, 데몬, 소속 미확인 프로세스에 대한 직접 종료 신호 전송.
- `purge`, 캐시 일괄 삭제, 스왑 파일 삭제, 앱 삭제, 파일 정리.
- 자동 강제 종료, 반복 종료, 관리자 권한 상주 도구, 보안 기능 해제.
- 작업 완료, 데이터 무손실 저장, 확보 메모리 용량, 성능 향상의 보장.

정상적인 0% CPU 사용률은 유효할 수 있다. 특정 시험에서 양수 결과를 요구하는 조건을 일반적인 종료 판단이나 전체 표본의 유효성 조건으로 확대하지 않는다.

## 3. 대상 분류와 필수 보호 정책

| 대상 | v1 정책 |
| --- | --- |
| 현재 사용자에 속한 지원 대상 `.regular` 앱 | 필수 정보 및 보호 조건을 모두 확인한 뒤 일반 종료 요청 가능 |
| `.accessory`·`.prohibited` 앱 | 관찰 전용 |
| Terminal·iTerm·Xcode·VS Code 등 하위 작업 호스트 앱 | 초기 기본 보호. GUI 앱이라는 이유로 안전하다고 취급하지 않음 |
| root 소유 프로세스·시스템 핵심 대상·다른 사용자·본 앱 | 종료 차단 |
| CLI·터미널 자식·데몬·소속 미확인 프로세스 | 관찰 전용 |

소유자 정책은 `allowedUID != 0`, `snapshot.uid != 0`, `snapshot.uid == allowedUID`를 서로 다른 조건으로 다룬다. 전달받은 `allowedUID`를 확인하는 것과 실제 실행 권한을 OS에서 확인하는 것은 다르며, 후자는 통합 시험에서 연결해야 한다.

사용자 보호 변경은 설정에서 명시적으로 수행한다. 종료 확인창에서 일회성으로 보호를 우회하지 않는다. 보호 목록 조회 실패는 보호 대상이 없다는 뜻이 아니며, 종료 엔진에서 요청을 차단해야 한다. UI 비활성화만으로 보호를 구현했다고 보지 않는다.

## 5. 구성 요소와 식별자

| 구성 요소 | 책임 |
| --- | --- |
| StatusCollector / DarwinStatusCollector | 허용된 범위의 상태·자원 통계 수집. 순수 계산부와 OS 어댑터 분리 |
| ProcessClassifier / 초기 명칭 JudgmentEngine | 관측 사실 표시와 대상 정책 적용. 불필요한 프로세스 추정 금지 |
| ProtectionStore | 기본·사용자 보호 규칙과 조회 실패 상태 관리 |
| CPUUsageCalculator | 주입된 표본의 순수 계산·거절 사유 반환 |
| TerminationStateMachine / TerminationEngine | 중복 차단, 최종 검증, 요청·관측 상태 관리 |
| MenuBarUI·기록부 | 상태와 제한을 표시하고 설정·결과를 로컬 기록 |

영속 보호 식별자는 앱 재실행 후에도 유지할 앱 식별자 또는 정규화 경로다. 실행 식별자는 `PID + 시작 시각(초·마이크로초)`다. 내부 요청에는 별도 `RequestID`를 부여한다.

선택 당시의 `NSRunningApplication` 객체와 실행 식별 정보를 보존한다. Swift의 참조 동일성 `===`를 프로세스 생존이나 동일 실행의 근거로 사용하지 않는다. 객체 비교가 PID·시작 시각·소유자 재검증을 대신하지 않는다.

사용자 공간의 조회와 종료 요청이 OS 전체에서 원자적이라고 주장하지 않는다. 신원이 달라지거나 확인되지 않으면 중단하고, 새 실행에 이전 선택·승인을 승계하지 않는다.

## 6. 종료 엔진 실행 순서 및 상태 관리

### 직렬화된 실행 순서

1. 실행 인스턴스의 중복 요청 확인과 처리 중 등록을 중단 없는 하나의 처리로 수행한다.
2. 종료 관측 등록을 요청보다 먼저 준비한다.
3. 요청 직전에 실행 식별 정보·소유자·대상 분류·최신 보호 규칙을 재검증한다.
4. 최종 검증 이후 호출 전까지 `await` 중단을 두지 않는다. 중단됐다면 재개 후 검증을 다시 수행한다.
5. `요청 중` 상태를 기록하고 `NSRunningApplication.terminate()`를 호출한다.
6. 전송 결과와 실제 종료를 구분한다. 빠른 종료 확인을 뒤늦은 반환값·타이머가 대기 상태로 되돌리지 못하게 한다.

보호 변경과 요청 상태의 직렬화 범위도 명시해야 한다. Actor 사용만으로 비동기 중단을 포함한 모든 절차가 원자적이라고 보지 않는다. 실제 프로세스 정보와 앱 설정의 보호 규칙은 각각 조회해 종료 엔진에서 결합한다.

### 관측 기반 상태표

| 조건 | 결과 |
| --- | --- |
| 선택한 실행이 이미 종료됐음을 확인 | `대상 이미 종료됨 — 요청 미전송` |
| 신원 조회 실패·불완전 반환·실행 교체·보호 적용 | `요청 차단 — 요청 미전송` |
| 일반 종료 요청 전송 실패 | `요청 전송 실패` — 자동 재시도 금지 |
| 요청 전송 성공, 종료 미확인 | `종료 대기` |
| 관찰 제한 시간 경과 | `제한 시간 내 종료 미확인` — 강제 종료 전환 금지 |
| 해당 실행의 종료 관측 | `종료 확인` |
| 제한 시간 이후 종료 관측 | `종료 확인 — 제한 시간 이후` |
| 같은 앱의 새 실행 관측 | 별도 실행 기록. 이전 승인·타이머 승계 금지 |

조회 실패를 대상 종료로 해석하지 않는다. `종료 확인`은 저장 완료나 업무 완료의 보장이 아니다. 요청 전 취소는 선택 해제이며, 요청 후 취소는 관찰 중단이다. 이미 전달한 종료 요청을 취소했다고 표시하지 않는다.

### 이벤트 귀속

`RequestID`는 앱 내부 식별자이며 macOS 전역 알림이 자동으로 돌려주는 값이 아니다.

- 요청별 타이머: 생성 당시 `(ExecutionInstanceID, RequestID)`를 보존하고 유효성을 대조한다.
- KVO: 보존한 앱 객체와 관찰 등록 정보를 연결한다.
- NSWorkspace 종료 알림: 알림의 앱을 보존한 실행 기록에 대응시킨 뒤 관련 요청 기록을 조회한다.

요청 상태와 실행의 종료 사실은 별도로 기록한다. 오래된 타이머가 새 요청을 오염시키지 않게 하되, 종료 사실 자체를 특정 요청의 성공 인과관계로 단정하지 않는다. 이미 확인한 종료 상태는 타임아웃으로 덮어쓰지 않는다.

## 7. CPU·시간 환산 계약

### 시간축과 계산

간격 측정은 `Date()`가 아니라 단조 시계를 사용한다. 현재 명세의 경과시간 경로는 `CLOCK_UPTIME_RAW` 또는 올바르게 환산한 `mach_absolute_time()`이다. 이미 나노초인 값에 Mach 변환비를 다시 적용하지 않는다.

CPU 누적시간은 공개 소스를 대조한 이전 설계에 따라 Mach timebase 환산을 적용한다. 실제 대상 OS·SDK의 반환 단위와 연결은 3단계 검증 대상으로 남긴다.

```text
CPU% = (구간 사용자 CPU 시간_ns + 구간 시스템 CPU 시간_ns)
       / 실제 단조 경과시간_ns × 100
```

동일 실행·동일 표본 세대의 두 표본만 비교한다. 첫 표본, 0 이하 경과시간, 카운터 역전, 조회 실패, 잠자기 복귀 또는 세대 변경 시에는 기준점을 다시 설정하거나 거절한다. 단일 코어 100% 기준이며 100% 초과값을 임의로 자르지 않는다.

### 정수 환산

```text
q = floor(ticks × numer / denom)
```

`numer > 0`, `denom > 0`을 생성 시 보장한다. `multipliedFullWidth`로 얻은 곱의 `(high, low)`에 대해 `high < denom`일 때만 `dividingFullWidth`로 몫을 구한다. 그 외에는 범위 초과로 거절한다. CPU 증가량 합산도 오버플로를 검사한다.

표현 가능한 결과에서는 정수 나노초 몫을 정확히 반환한다. 소수 나노초는 버리므로 원래 유리수와의 차이는 1ns 미만이다. 이를 모든 입력에서 물리적 시간이 ‘0ns 오차’라고 표현하지 않는다. CPU 백분율의 최종 부동소수점 표현과 정수 시간 환산의 정확성도 구분한다.

| 검토에 사용된 입력 | 정수 기준 결과 |
| --- | --- |
| `(2^63 − 1024) × 2 / 1` | `18446744073709549568 ns` |
| `(2^53 + 1) × 2 / 3` | `6004799503160662 ns` |
| `2^63 × 2 / 1` | `2^64`: UInt64 범위 초과, 거절 |
| `1 × 1 / 3` | `0 ns`: 소수 부분 버림 |

### 작은 CPU 기대값 시험

`200 / 2^63 × 100 ≈ 2.168404344971009e-15%`인 사례는 `percentage > 0.0`과 절대 허용오차 `1e-27`을 함께 검사하도록 수정됐다고 보고됐다 [S3]. 기존 기본 허용오차 `0.0001`로는 잘못된 0도 통과할 수 있었다. 양수 검사는 이 특정 입력의 기대 조건이지 모든 CPU 표본의 조건이 아니다.

## 8. 메모리·스왑·압박 이벤트

`host_page_size()`로 페이지 크기를 확인한다. `host_statistics64`의 상태와 반환 요소 수를 확인한 뒤 사용하는 필드만 환산한다. `HOST_VM_INFO64_COUNT`는 바이트가 아니라 `integer_t` 단위 요소 수라는 검토 조건을 적용한다.

| 표시 항목 | 명세의 계산 |
| --- | --- |
| Wired | `wire_count × pageSize` |
| Active | `active_count × pageSize` |
| Compressed | `compressor_page_count × pageSize` |
| Free — speculative 제외 | `(free_count − speculative_count) × pageSize` |

위 항목은 선택된 Mach VM 통계이며 전체 메모리의 완전한 분할이나 활성 상태 보기와 동일한 합계라고 표시하지 않는다. 차감·곱셈의 범위와 조회 실패를 검사한다.

`vm.swapusage`는 OS가 보고한 사용량·전체 용량을 표시한다. 스왑 사용량 하나만으로 병목을 단정하지 않는다. 메모리 압박 이벤트는 수신 전 `감시 중 · 이벤트 미수신`, 수신 후 마지막 상태와 수신 시각을 표시한다. 이를 활성 상태 보기의 현재 그래프 수치와 동일시하지 않는다.

## 9. 기존 검토 지적과 최종 반영 상태

| 기존 지적 | 반영 내용 및 증거 한계 |
| --- | --- |
| 작업 증거 없음 → 종료 후보로 추정 | 관측·불확실성 표시로 명세 변경 |
| UID·생존 정보가 있으나 검사 누락 | 소유자·생존 검증 및 차단 시 호출 0회 검사 추가 보고 [S2] |
| UID 일치만으로 root 차단했다고 설명 | 실행 문맥 UID 0과 대상 UID 0을 독립 차단하도록 후속 수정 보고 [S3] |
| 보호 조회 실패와 비보호 상태 혼동 | 보호·비보호·조회 실패 결과 분리 및 실패 시 차단 [S2] |
| 정수 변환·합산의 비정상 종료 | 합산 범위 검사와 환산 실패 거절로 수정. 이후 전폭 정수 환산으로 재수정 [S2, S3] |
| 유효한 큰 시간값 거절·Double 반올림 | 전폭 정수 환산으로 변경한 코드 조각 제공. 이전 검토의 함수 독립 시험 기록과 구분 [S3, S4] |
| 단언문 없이도 PASS | 단언문 0개 실패 처리, 요청 ID 부재 시 실패 기록 [S2] |
| 작은 기대값에 너무 큰 허용오차 | 양수 단언문과 `accuracy: 1e-27` 추가 보고 [S3] |
| `swift test`와 자체 러너 실행 혼용 | 확인된 명령은 `swift run MacTaskCleanerTestsRunner`로 기록 [S2, S3] |

이전 검토에서 보고된 환산 함수의 독립 검사는 고정 입력 20개 + 시드 고정 입력 256개 = 276개, 불일치 0개였다 [S4]. 이는 함수 조각과 생성자 조건의 검사이며 최신 전체 패키지의 32개·53개 재실행 증거가 아니다. 이번 문서 작성에서는 해당 시험을 다시 실행하지 않았다.

## 10. 시험 계층과 다음 단계

| 단계 | 범위 | 현재 기록 |
| --- | --- | --- |
| 1. 순수 계산 | 시간 환산·CPU 비율·이상/경계값 거절 | 최신 사용자 보고 14개 테스트 통과 |
| 2. 모의 상태 머신 | 보호·중복·실패·타임아웃·늦은 종료·실행 격리 | 최신 사용자 보고 18개 테스트 통과 |
| 3. macOS 통합 | 실제 API·신원·AppKit 종료 및 알림 연결 | 계획 검토. 실제 결과 미제공 |
| 4. M1 실측 | CPU·메모리·장기 동작 | 미검증 |

모의 시험에서는 차단 결과뿐 아니라 종료 요청 호출 횟수 0회를 확인한다. 단언문 미실행, 거절 결과를 무조건 성공시키는 분기, 단순 순차 시험을 동시 경합 시험으로 표현하는 것을 금지한다. 세대 번호 불일치 시험과 실제 잠자기 이벤트 연결 시험을 구분한다.

### 3단계 진입 조건 [S4]

1. 더미는 단순 대기 실행 파일이 아니라 `NSApplication` 생명주기와 일반 종료 응답을 갖춘 `DummyTestTarget.app`으로 구성한다. `.regular` 조건을 충족하고 정책 우회를 하지 않는다.
2. 지정된 시험 앱 URL을 실행하고 반환된 앱 객체·PID·시작 시각·UID·실행 경로를 보존한다. 이번 시험이 직접 생성한 실행에만 종료 요청을 허용한다.
3. 종료 알림은 `NSWorkspace.shared.notificationCenter`에 요청 전에 등록한다. 메인 실행 루프를 동기 대기로 막지 않는다.
4. `PROC_PIDTBSDINFO`의 신원과 반환 바이트 수를 확인한다. CPU 수집까지 연결한다면 별도 `PROC_PIDTASKINFO`와 실제 시간 단위를 확인한다.
5. 요청 시각, 반환값, 종료 속성 관측, 알림 수신, 최종 상태를 각각 기록한다. 이벤트 도착 순서를 하나로 가정하지 않는다.
6. 읽기 전용 수집, 더미 정상 종료, 지연 종료, 재실행 격리를 검사한다. 사용자 앱·시스템 앱을 시험 대상으로 사용하지 않는다.
7. 실패 시 `sudo`, `kill`, `pkill`, `killall`, `forceTerminate()`로 대체하지 않는다. 더미 자체 제한 시간 종료는 별도 사유로 기록하고 일반 종료 요청의 성공으로 계산하지 않는다.

실제 AppKit 객체를 보존한 실행 기록에 대응시키는 구현, 보호 규칙의 실제 조회, UID의 신뢰 가능한 출처, 잠자기 복귀 연결은 통합 단계에서 확인할 사항이다. 모의 시험 통과가 이 연결의 성공을 의미하지 않는다.

## 11. 성능 목표와 패키징

대기 중 5초·상세창 2초는 제안된 조회 주기이지 성능 달성 증거가 아니다. 앱 생명주기 변화에는 이벤트 알림을 활용하는 설계를 유지한다.

- 목표: 대기 상태 평균 CPU 1% 이하(단일 코어 기준), `ri_phys_footprint` 관측 최대 100MB 이하.
- 평균 CPU: `유효 구간 CPU 시간 증가량 합 / 실제 단조 경과시간 합 × 100`.
- 메모리: resident size나 Allocations 힙 합계를 physical footprint와 혼용하지 않음. 이산 표본의 최대값은 표본 사이 순간 최대값의 증명이 아님.
- 기록: macOS·툴체인 버전, Release 빌드, 프로세스 수, 창 상태, 최소 10분 측정 구간, 측정 도구 영향, 장기 누적 검증 여부.

실측 전 ‘달성’, ‘초경량’, ‘최적 성능’을 확정하지 않는다. 짧은 테스트 러너 실행시간을 성능 시험으로 대체하지 않는다.

구현 방향은 Swift·SwiftUI/AppKit·SPM이다. `MenuBarExtra`에 `.menuBarExtraStyle(.window)`를 적용한다. CLI 빌드에도 적절한 macOS SDK·개발 도구가 필요하며, 실행 파일 빌드와 `.app` 번들·Info.plist·권한·서명·공증은 구분한다. 이 문서가 현재 OS 호환성이나 배포 성공을 인증하지 않는다.

## 12. 인계 및 보존 규칙

다음 구현자는 전체 설계 논의를 반복하기보다 위 범위와 실제 시험 결과를 연결한다. 최신 파일·실행 명령·전체 출력·해당 명령의 종료 코드·시험한 커밋을 함께 보존한다. 문서만으로 최신 코드에 모든 가드가 배치됐다고 추정하지 않는다.

문서 추가 시 기존 README와 소스는 변경하지 않는다. 다른 프로젝트 자료, 계정·인증정보, 개인 사용자 경로, 호스트 이름, 전체 프로세스 목록은 이 공개 문서에 포함하지 않는다. 첨부 원본·기존 재현 ZIP·원시 로그는 이번 업로드 대상이 아니다.

최종 검토 의견은 **추가 재설계보다 전용 더미 앱에 한정한 3단계 연결 검증으로 진행하는 방향**이다. 이는 실제 업무 앱 종료 시험이나 실사용 배포 승인과 다르다.
